# 编码规范
## 通用规范
-   避免不必要的对象复制或克隆（优先依赖注入，避免 clone 与重复 new）
-   避免多层嵌套，使用提前返回，嵌套层级不超过 3 层
-   使用适当的并发控制机制（Redis 分布式锁、队列、原子操作）
-   严禁在全局变量或静态变量中保存请求态数据（Webman 常驻内存模式）
-   所有方法必须声明参数类型与返回值类型
## 代码可读性
### 命名约定
-   使用有意义、描述性的名称
-   遵循PSR规范（PSR-12）
-   类名使用 PascalCase
-   方法与变量使用 camelCase
-   避免缩写和单字母变量（循环变量 i/j 除外）
-   Service / Repository / Controller 命名必须体现职责
-   禁止使用魔法字符串，使用枚举（Enum）或常量替代
### 代码组织
-   相关代码放在一起，遵循 Webman 推荐目录结构
-   Controller 只负责请求分发与响应
-   Service 负责业务逻辑
-   Repository 负责数据访问
-   Model 不编写复杂业务逻辑
-   一个函数只做一件事（单一职责原则）
-   保持适当抽象层次，避免过度封装
### 注释与文档
-   注释解释"为什么"，而不是"做什么"
-   所有公共方法必须提供 PHPDoc
-   修改代码必须同步更新注释
-   复杂业务必须补充流程说明
-   API 必须提供参数、返回值、异常说明
# 性能优化
## 内存优化（Webman 重点）
-   避免不必要的对象创建
-   大数组、临时变量使用后及时释放（unset）
-   禁止静态变量保存请求数据
-   严禁缓存用户态信息到单例对象
-   使用连接池而非频繁创建连接
-   及时关闭文件、流、Socket 资源
-   避免闭包持有大对象引用导致内存无法释放
## 计算优化
-   避免重复数据库查询
-   避免重复计算，使用缓存变量
-   合理使用缓存（Redis / 本地缓存）
-   使用合适的数据结构（哈希查找优于循环查找）
-   能用 SQL 聚合就不要在 PHP 中循环统计
-   延迟计算直到必要时（懒加载）
-   避免 N+1 查询问题
## 并行优化（高并发强化）
-   识别可并行任务（通知、日志、第三方调用）
-   使用队列异步处理耗时任务
-   避免阻塞IO操作
-   避免sleep等阻塞函数
-   使用Redis原子操作代替应用层锁
-   注意单例、静态属性的线程安全问题
-   避免不必要的锁与同步操作
# 安全规范（Web 必须）
-   所有 SQL 必须使用参数绑定
-   输出必须进行 XSS 过滤
-   必须进行 CSRF 校验
-   所有外部输入必须验证（DTO + Validator）
# 异常处理规范
-   禁止吞异常
-   必须记录 error 日志
-   业务异常与系统异常分离
-   统一异常返回格式
# 日志规范
-   按级别记录日志（debug/info/warning/error）
-   高并发场景避免过量日志输出
-   敏感信息必须脱敏
# 高并发核心原则
-   Webman 是常驻内存模型，不会自动释放变量
-   所有代码必须假设会被调用 100 万次
-   禁止依赖请求结束自动清理状态
-   必须关注内存增长趋势
-   所有全局状态必须可控、可重置
# 协程规范（Webman Coroutine）
-   **上下文隔离**：严禁使用全局变量/静态变量存储请求级数据，必须使用 `support\Context`
-   **禁止阻塞**：禁止使用 `sleep`、`exit`、`die`，避免原生阻塞 I/O（如 `file_get_contents` 抓取 URL）
-   **全局变量污染**：警惕静态数组/对象在不同请求间的数据污染
-   **原子性保障**：并发修改共享数据（如统计）必须使用原子操作或 Redis 锁
-   **连接复用**：强制使用框架提供的 Database/Redis 连接池，禁止手动创建短连接
-   **一处协程，处处协程**：确保调用链上的所有 I/O 操作均支持协程（或使用 Hook 机制）
# 质量要求
-   PHP 8.1+
-   启用 strict_types
-   使用静态分析工具（PHPStan / Psalm）
-   核心业务必须单元测试覆盖
-   代码提交必须通过 CI 检查
